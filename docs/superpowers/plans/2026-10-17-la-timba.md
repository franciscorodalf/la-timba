# La Timba — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Web gratuita en Cloudflare para jugar con amigos a Blackjack y Carrera de caballos en partidas con código, con fichas y ranking globales.

**Architecture:** Un único Cloudflare Worker sirve la SPA (React) y la API. Cuatro Durable Objects con SQLite: `Jugadores` (global: perfiles, fichas, ranking), `Partida` (sala por código) y `MesaBlackjack`/`MesaCarrera` (una por código). Las reglas de cada juego son funciones puras en `src/shared/` que la clase base `Mesa` ejecuta y difunde por WebSocket (PartyServer).

**Tech Stack:** TypeScript, Cloudflare Workers + Durable Objects (SQLite), PartyServer / partysocket, React 18.3, Vite + `@cloudflare/vite-plugin`, Motion (`motion/react`), wouter, `@letele/playing-cards`, `qrcode.react`, `@fontsource/playfair-display` + `@fontsource/inter`, Vitest ≥ 4.1 + `@cloudflare/vitest-plugin`, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-17-la-timba-design.md`

## Global Constraints

- Coste 0 €: solo plan gratuito de Cloudflare; ningún servicio que pida tarjeta.
- Apodo: 3–16 caracteres `[A-Za-z0-9_]`, único sin distinguir mayúsculas. PIN: exactamente 4 dígitos.
- Fichas iniciales 1.000. Rescate +200, solo con 0 fichas y sin apuestas pendientes; suma 1 quiebra.
- PIN: PBKDF2-SHA256, 10.000 iteraciones (cabe en los 10 ms de CPU por invocación del plan gratuito), sal de 16 bytes. 5 fallos → bloqueo 15 min.
- Token: HMAC-SHA256 con `TOKEN_SECRET`, caduca a los 30 días, guardado en `localStorage` (clave `timba.token`).
- Código de partida: 4 caracteres de `ABCDEFGHJKMNPQRSTUVWXYZ23456789`. La partida se cierra tras 30 min sin conexiones.
- Blackjack: 6 barajas, rebarajar con < 25 % (78 cartas), apuestas 15 s, decisiones 15 s, apuesta 10–500, máx. 6 jugadores, banca pide hasta 17 y se planta en cualquier 17+, blackjack 3:2 (parte fraccionaria redondeada hacia abajo), ganar 1:1, empate devuelve.
- Carrera: ases = caballos, 7 tramos, una carta cada 800 ms, apuestas 20 s, 10–500 por caballo (acumulado), pago ×4 apuesta incluida, máx. 12 jugadores.
- Límite: 20 mensajes/s por conexión (exceso descartado con error); más de 60 en el mismo segundo → cerrar conexión con código 4008.
- Barajado siempre con `crypto.getRandomValues`; nunca `Math.random` en el servidor.
- Colores: tapete `#1d7a4c → #0f5132 → #08361f`, madera `#5a3a1e`/`#8b5e34`, oro `#d4af37`, crema `#f3e7c4`, rojo `#b3122e`, reverso `#7a1020`. Tipografía: Playfair Display (títulos y cifras), Inter (interfaz).
- Animaciones solo con `transform` y `opacity`; con `prefers-reduced-motion: reduce` se sustituyen por fundidos. Botones ≥ 44 px de alto.
- Error de servidor no esperado en la API → 503 y el cliente muestra «La Timba está descansando, vuelve mañana».
- Todos los textos de la interfaz en español.
- Cada commit termina con la línea `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- **Código en minúsculas** (`kxp4` tecleado en el móvil): debe llevar a la misma partida que `KXP4` → test en Task 9.
- **El mismo jugador con dos pestañas o dispositivos** en la misma mesa: un solo asiento, ambas pestañas ven la misma mano y una acción se aplica una vez; cerrar una pestaña no lo desconecta → test en Task 10.
- **Entrar a una mesa con la ronda empezada**: mira la ronda sin cartas y puede apostar en la siguiente → test en Task 10.
- **Cantidades de apuesta raras** (`0`, `-10`, `50.5`, `"50"`, `501`, más fichas de las que tienes): error y ninguna ficha descontada → tests en Task 3 y Task 7.
- **Todos se van de la mesa a mitad de ronda**: la ronda se liquida (las apuestas pendientes desaparecen) y la mesa deja de programar alarmas (no consume cuota) → test en Task 10.

### Task 4: Máquina de estados del blackjack

**Files:**
- Modify: `src/shared/juegos/blackjack.ts`
- Create: `test/shared/blackjack-mesa.test.ts`

**Interfaces:**
- Consumes: Task 2, Task 3.
- Produces:
```ts
export type AccionBJ = { t: "apostar"; cantidad: number } | { t: "pedir" } | { t: "plantarse" } | { t: "doblar" } | { t: "salir" };
export type FaseBJ = "esperando" | "apuestas" | "decisiones" | "banca" | "resultado";
export interface ManoBJ { jugadorId: JugadorId; apodo: string; apuesta: number; cartas: Carta[]; estado: "jugando" | "plantado" | "pasado" | "blackjack"; doblada: boolean; abandonada: boolean }
export interface EstadoBJ { ronda: number; fase: FaseBJ; finFase: number | null; zapato: Carta[]; banca: Carta[]; asientos: { jugadorId: JugadorId; apodo: string; conectado: boolean }[]; manos: ManoBJ[] }
export interface VistaBJ { ronda: number; fase: FaseBJ; finFase: number | null; banca: (Carta | null)[]; totalBanca: number | null; manos: (Omit<ManoBJ, "abandonada"> & { total: number })[]; sentados: string[]; yo: JugadorId | null }
export const blackjack: Juego<EstadoBJ, AccionBJ>;
```
Transiciones (todas con `ahora` explícito):
- `esperando` → al sentarse el primero: `apuestas`, `finFase = ahora + APUESTAS_MS`.
- `apuestas`: `apostar` válido una vez por ronda → crea `ManoBJ` vacía. En `tick` vencido: sin apuestas → nueva ventana de `apuestas` (o `esperando` si no queda nadie sentado); con apuestas → reparte jugador, banca, jugador, banca (eventos `carta_repartida { a: jugadorId | "banca", oculta }`, la segunda de la banca `oculta: true` y **sin** carta en el evento), marca `blackjack`, pasa a `decisiones` con `finFase = ahora + DECISIONES_MS`.
- `decisiones`: `pedir` (pasa de 21 → `pasado`), `plantarse`, `doblar` (solo con 2 cartas: `costo` = apuesta, duplica apuesta, 1 carta, queda `plantado` o `pasado`). Cuando ninguna mano está `jugando` → `banca` con `finFase = ahora + BANCA_MS`. Tick vencido → planta las que sigan jugando → `banca`.
- `banca` (tick): evento `carta_girada`; si alguna mano no está `pasado`, pide mientras `bancaDebePedir`; calcula `pago` por mano (`abandonada` → 0); devuelve `liquidacion { ronda, filas }` y eventos `pago { jugadorId, neto }`; pasa a `resultado` con `finFase = ahora + RESULTADO_MS`.
- `resultado` (tick): `ronda + 1`, vacía manos y banca; si `zapato.length < MIN_ZAPATO` rebaraja 6 barajas nuevas (evento `barajado`); `apuestas` si hay sentados, si no `esperando`.
- `salir`: quita el asiento; si tenía mano en juego, `abandonada = true` (pierde). `desconectar`: `conectado = false` y, si está `jugando` en `decisiones`, se planta; `sentar` vuelve a poner `conectado = true`. En el tick de `resultado` se eliminan los asientos con `conectado = false`; sin asientos → `esperando` (sin alarma).
- `costo`: `apostar` → `cantidad`; `doblar` → `apuesta` de su mano; resto 0.
- `proximaAlarma`: `finFase` (null en `esperando`).
- `vista`: nunca incluye `zapato`; `banca[1]` es `null` y `totalBanca` cuenta solo la carta visible mientras `fase` sea `apuestas` o `decisiones`.

**Interfaces:**

export type AccionCarrera = { t: "apostar"; caballo: Palo; cantidad: number } | { t: "salir" };
export type FaseCarrera = "esperando" | "apuestas" | "carrera" | "resultado";
export interface EstadoCarrera { ronda: number; fase: FaseCarrera; finFase: number | null; mazo: Carta[]; descartes: Carta[]; tramos: Carta[]; tramosGirados: number; posiciones: Record<Palo, number>; apuestas: { jugadorId: JugadorId; caballo: Palo; cantidad: number }[]; asientos: { jugadorId: JugadorId; apodo: string; conectado: boolean }[]; abandonos: JugadorId[]; ganador: Palo | null }
export interface VistaCarrera { ronda: number; fase: FaseCarrera; finFase: number | null; posiciones: Record<Palo, number>; tramos: (Carta | null)[]; ultimaCarta: Carta | null; misApuestas: { caballo: Palo; cantidad: number }[]; totalesPorCaballo: Record<Palo, number>; sentados: string[]; ganador: Palo | null }
export const CARRERA = { TRAMOS: 7, META: 8, PASO_MS: 800, APUESTAS_MS: 20_000, RESULTADO_MS: 5_000, MIN: 10, MAX: 500, PAGO: 4, MAX_JUGADORES: 12 } as const;
